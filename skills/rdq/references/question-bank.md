## 使用規則

- 象限Ⅲ依「不問會導致多少返工」排序。
- 選項加上「不確定／其他」；每輪最後提供「先這樣，直接開始」。
- 象限Ⅳ每次只選 3–5 項，每項附代價；不預設採納。
- 題庫是選題來源，不是每次全部詢問的清單。

## 教育研習與演講

### 象限Ⅲ訪談題

| 題目 | 具體選項方向 | 不問的風險 |
|---|---|---|
| 學員的 AI 使用程度？ | 未註冊／只問過問題／已用於工作／程度落差大 | 起點錯誤會重排內容與示範深度 |
| 能否現場登入或安裝？ | 個人帳號／公務帳號受限／不能登入／未成年限制 | 動手做可能整段失效 |
| 裝置與網路？ | 個人筆電／不能安裝的電腦教室／只有手機／尚未實測 | CLI 或線上活動可能無法進行 |
| 時間與活動比例？ | 60–90 分鐘示範／半天含實作／全天／系列課 | 內容容量與教材結構差異巨大 |
| 是否錄影或公開？ | 不錄影／校內／未列出／公開直播或 YouTube | 素材授權與個資處理不同 |
| 主辦要求的交付物？ | 投影片／課程大綱／公開資源頁／學員成品 | 最終格式錯誤會整份重做 |

### 象限Ⅳ建議

- 為登入與註冊步驟準備短操作影片及可直接修改的完成品 — 多 1–2 小時準備，但能避免現場卡關。
- 準備斷網可用的離線版本或紙本替代活動 — 需要維護兩版，但網路故障時仍能完成課程。
- 事前與主辦約定錄影、入鏡、學生作品及第三方素材範圍 — 多一次溝通，避免事後下架或重剪。
- 固定加入學生個資、生成內容標示、著作權與學術誠信提醒 — 佔用數分鐘，但降低學校與家長疑慮。
- 設計課後追蹤管道或具體行動題 — 增加後續回覆成本，但較能知道學員是否真的實作。

## 教學簡報與投影片

### 象限Ⅲ訪談題

| 題目 | 具體選項方向 | 不問的風險 |
|---|---|---|
| 誰站在台上使用？ | 自己講／交給別人講／學生自學／現場與留檔兼用 | 資訊密度完全不同 |
| 最終檔案？ | HTML／PPTX／Google Slides／PDF | 平台與播放方式不同 |
| 現場網路？ | 穩定／不保證／不能連外／只能使用主辦電腦 | 線上互動可能整份失效 |
| 是否即時作答？ | 不需要／口頭或小白板／手機 QR／共用一台電腦 | 決定是否需要後端與部署 |
| 投影設備與觀看距離？ | 16:9 單槍／4:3 老設備／大螢幕／手機觀看 | 比例與最小字級是全域決策 |
| 時間與動手比例？ | 45 分鐘講述／45 分鐘含實作／3 小時／短講 | 頁數及段落骨架不同 |

### 象限Ⅳ建議

- 鎖定最小字級並以手機縮圖檢查可讀性 — 內容量會下降，但後排更容易看清。
- 不讓顏色成為唯一資訊來源，同時使用文字、形狀或圖示 — 增加標記工作，但提升無障礙與投影容錯。
- 做離線降級版並將必要媒體存成本機檔 — 檔案變大，但現場不依賴網路。
- QR Code 同時附短網址或房號 — 佔用版面，但相機或網路出問題時有替代入口。
- 分成現場版與可獨立閱讀的留檔版 — 需要維護兩份輸出，但事後閱讀不依賴講者口述。

## 備課教材與課程設計

### 象限Ⅲ訪談題

| 題目 | 具體選項方向 | 不問的風險 |
|---|---|---|
| 學生最後如何使用？ | A4 紙本／投影簡報／自學網頁／教師教案 | 留白、資訊密度與互動方式不同 |
| 學生實際起點？ | 前置紮實／有概念破洞／複習／需要往回補 | 例題梯度與順序會重排 |
| 教材涵蓋時間？ | 45 分鐘／90 分鐘／4–6 節／可拆模組 | 內容量是架構決策 |
| 對齊哪個版本或課綱？ | 康軒／翰林／南一／只對齊課綱 | 名詞、符號與進度可能不一致 |
| 是否差異化？ | 單一版本／基礎加挑戰／三層／特教調整版 | 事後拆層次通常需要重排 |
| 評量形式？ | 課本習題／即時檢核／小考／實作 rubric | 評量與教學目標可能脫節 |

### 象限Ⅳ建議

- 每道題與答案用另一種解法獨立驗算 — 增加驗證時間，但降低課堂上答案錯誤的風險。
- 從同一來源輸出學生版與教師解析版 — 初期需要標記內容層級，之後不用手動刪答案。
- 檢查物價、單位、地名與生活情境是否符合學生經驗 — 多一道人工掃描，避免情境失真。
- 特教調整優先改呈現方式：大字、一頁一題、單一步驟指令 — 多一個版面版本，但不必簡化學習目標。
- 公開前清除課本掃描、未授權圖片與可識別學生資料 — 增加素材替換時間，降低著作權與個資風險。

## 影片內容

### 象限Ⅲ訪談題

| 題目 | 具體選項方向 | 不問的風險 |
|---|---|---|
| 觀眾已經會什麼？ | Agent 重度使用者／一般 ChatGPT 使用者／AI 新手／行政決策者 | 腳本密度與例子不同 |
| 畫面有無敏感內容？ | 全部自製／學生資料／第三方素材／金鑰與通知 | 公開後可能無法補救 |
| 單支、系列、短片或直播？ | 8–15 分鐘／系列／Shorts／直播 | 命名、模板與腳本結構不同 |
| 畫面怎麼產生？ | 螢幕錄影／真人出鏡／生成素材與配音／重剪舊片 | 工時與逐字稿需求差異大 |
| 上架範圍？ | 公開／未列出／現場離線播放／嵌入教材 | SEO、下載與長期連結策略不同 |
| 看完要採取什麼行動？ | 留下印象／跟做／轉發／點擊或報名 | 節奏與配套教材不同 |

### 象限Ⅳ建議

- 上片前逐段檢查金鑰、分頁、檔名、通知與學生姓名 — 多 5–10 分鐘，避免敏感資訊被截圖。
- 保存音樂、圖片及第三方素材的授權證明 — 素材選擇變少，但降低下架或收益被認領的風險。
- 重要影片先未列出，請 2–3 人試看後再公開 — 延後一天，但能在網址與觀看資料累積前修正。
- 開頭先展示成品與觀看收穫，縮圖文字控制在短句 — 增加腳本與封面設計時間，但提高理解速度。
- 腳本預留可獨立切成短片的段落與章節時間碼 — 前期設計較慢，但同一素材可重複使用。

## 程式與網頁專案

### 象限Ⅲ訪談題

| 題目 | 具體選項方向 | 不問的風險 |
|---|---|---|
| 同時使用人數？ | 個人／一班／大型研習／離線工具 | 併發與後端需求不同 |
| 是否呼叫 AI、誰負擔金鑰？ | 不需要／個人本機／共用金鑰／使用者自備 | 金鑰不能安全放在前端 |
| 資料重整後是否保留？ | 不保留／同裝置／跨裝置／需匯出 | 決定儲存層與資料模型 |
| 是否需要身分？ | 匿名／暱稱／活動碼／正式登入 | 身分層牽動個資與安全規則 |
| 如何交付？ | 單一 HTML／靜態網站／伺服器／既有網站子頁 | 純前端與後端部署分歧 |
| 最差裝置與網路？ | 桌機／舊手機／大型共用 Wi-Fi／完全離線 | 版面與同步策略不同 |

### 象限Ⅳ建議

- 不把 API key 放在前端或 Git 歷史；學生端呼叫 AI 時使用代理層 — 增加部署複雜度，但避免金鑰外洩。
- 設定單次字數、每人次數及帳務警示 — 限制使用彈性，但避免費用失控。
- 資料庫一開始就設定安全規則與用量估算 — 多花設定時間，降低公開讀寫或活動中斷風險。
- 個資改用活動代號並規劃刪除期限 — 失去部分長期分析能力，但降低學生資料責任。
- 用 iPhone 與舊 Android 實測，並準備短網址 — 增加測試時間，避免現場部分裝置無法使用。
- 從第一版提供 JSON 或 CSV 匯出 — 多一段資料處理功能，但平台更換時能帶走資料。

## 通用

### 象限Ⅲ訪談題

| 題目 | 具體選項方向 | 不問的風險 |
|---|---|---|
| 最後交給誰？ | 自己／固定熟人／不特定使用者／審查單位 | 防呆、說明、授權與格式不同 |
| 絕對不能發生什麼？ | 可重做／不能覆蓋原檔／內容不能外流／有明文規定 | 不可逆錯誤代價高 |
| 在哪裡使用？ | 自己電腦／他人裝置／現場且網路不穩／長期網路存取 | 技術與交付方式不同 |
| 何時要可用？ | 今天／本週／固定死線／無死線 | 完整度與範圍選擇不同 |
| 可以花錢嗎？ | 完全免費／既有訂閱／小額／單位預算 | 工具選型可能整組更換 |
| 怎樣算成功？ | 自己認可／別人可自行完成／具體數字／通過審查 | 沒有驗收標準容易整體重做 |
| 一次性或重複使用？ | 一次／偶爾手改／固定套用／多人共用 | 過度或不足模板化 |
| 現在有什麼起點？ | 從零／零散素材／半成品／舊版改造 | 容易做出不相容的新版本 |

### 象限Ⅳ建議

- 先做結構完整但細節從簡的粗胚 — 第一版較陽春，但能提早修正方向。
- 準備壞掉時的離線、靜態或純文字備案 — 多維護一份替代品，降低現場中斷風險。
- 交付前檢查個資、機密、授權素材與公開範圍 — 多一道掃描，避免難以回收的外洩。
- 明確列出本次不做的功能，將加分項目留到下一階段 — 本次範圍較小，但更容易準時完成。
- 盤點既有檔案、模板、技能或專案後再決定是否重做 — 增加短暫盤點時間，可能大幅減少重工。
